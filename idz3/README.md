# ИДЗ №3 — АКОС

**Вариант 4. Читатели и писатели: чтение подтверждённых данных.**

В проекте собраны четыре реализации одной модели. Во всех вариантах читатели обращаются только к подтверждённой версии отсортированной базы, а писатели готовят новую версию по стадиям, проверяют её и только после этого публикуют.

## Что находится в проекте

| Каталог / программа | Назначение |
|---|---|
| `parent_named` | Родитель запускает дочерние процессы; POSIX shared memory и именованные POSIX-семафоры |
| `parent_unnamed` | Та же схема с неименованными семафорами `sem_init(..., pshared=1, ...)` в разделяемой памяти |
| `shm_init`, `shm_reader`, `shm_writer` | Независимо запускаемые процессы, POSIX shared memory и именованные семафоры |
| `mq_server`, `mq_reader`, `mq_writer` | Независимые процессы, POSIX message queue и именованные семафоры |

Общие структуры данных, проверка базы, генератор случайных значений и работа с семафорами находятся в `common/`.

## Сборка

Нужна Linux-система с поддержкой POSIX shared memory, POSIX semaphores и POSIX message queues. На большинстве современных дистрибутивов всё это уже доступно. Если `/dev/mqueue` не смонтирован, его можно подключить командой:

```sh
sudo mount -t mqueue none /dev/mqueue
```

Сборка всех программ:

```sh
make
```

Исполняемые файлы появятся в `bin/`.

Сборка через CMake:

```sh
cmake -S . -B build
cmake --build build -j
```

## Запуск первых двух вариантов

Без аргументов программа запросит параметры в консоли:

```sh
bin/parent_named
bin/parent_unnamed
```

Можно передать готовую конфигурацию:

```sh
bin/parent_named --config tests/data/basic.conf
bin/parent_unnamed --config tests/data/wait.conf
```

Поддерживаются аргументы `--config`, `--seed`, `--ops`, `--readers`, `--writers`, `--strategy`, `--read-ms`, `--prep-ms` и `--confirm-ms`. Аргументы после `--config` переопределяют значения из файла.

В конфигурационном файле используются строки `key=value`. Начальный массив задаётся через запятую:

```text
size=5
initial=2,5,8,12,19
readers=2
writers=1
ops=2
min=1
max=20
stages=3
strategy=READ_OLD
read_ms=0
prep_ms=10
confirm_ms=0
seed=42
```

`READ_OLD` разрешает читать предыдущую подтверждённую версию во время подготовки новой. `WAIT_NEW` заставляет читателя ждать публикации. Значение `ops=0` означает неограниченное число операций до Ctrl+C.

## Запуск независимых процессов с разделяемой памятью

Команды запускаются из корня `idz3`. В независимых вариантах поля `readers` и `writers` в конфигурации не запускают процессы автоматически: фактическое число участников определяется количеством выполненных команд запуска. Для SHM-сеанса значение `writers` должно совпадать с количеством запускаемых писателей, так как оно используется при пробуждении писателей во время общей остановки. Сначала создаётся сеанс:

```sh
bin/shm_init --config tests/data/wait.conf
```

Затем в отдельных терминалах можно запустить участников:

```sh
bin/shm_reader --id 1
bin/shm_reader --id 2
bin/shm_reader --id 3
bin/shm_writer --id 1
bin/shm_writer --id 2
```

Для просмотра состояния:

```sh
bin/shm_status
```

Остановить все процессы сеанса:

```sh
bin/shm_stop
```

После завершения участников удалить именованные семафоры и разделяемую память:

```sh
bin/shm_cleanup
```

Если процесс был аварийно уничтожен и счётчик активных участников не обнулился, после проверки, что старые процессы действительно завершились, допускается принудительная очистка:

```sh
bin/shm_cleanup --force
```

Параметр `--id` задаёт номер участника. Для нескольких процессов одной роли используйте разные номера.

## Запуск независимых процессов с очередью сообщений

Сначала запускается сервер. Он создаёт очередь запросов и именованные семафоры:

```sh
bin/mq_server --config tests/data/wait.conf
```

В других терминалах запускаются клиенты:

```sh
bin/mq_reader --id 1
bin/mq_reader --id 2
bin/mq_reader --id 3
bin/mq_writer --id 1
bin/mq_writer --id 2
```

Каждый клиент создаёт собственную очередь ответов. Читатели отправляют запросы серверу, писатели передают начало подготовки, стадии и запрос публикации. При `WAIT_NEW` сервер сохраняет запросы читателей до публикации или отмены версии.

Остановить сервер:

```sh
bin/mq_stop
```

После завершения сервера удалить очередь и именованные семафоры:

```sh
bin/mq_cleanup
```

Не запускайте `mq_cleanup`, пока сервер и клиенты ещё работают. Если сервер остановлен через Ctrl+C, клиенты обнаруживают завершение сервера и выходят.

## Завершение и очистка

В первых двух вариантах родитель дожидается всех дочерних процессов, затем удаляет созданные им IPC-ресурсы. Ctrl+C инициирует остановку участников; незавершённая подготовка отменяется, а последняя подтверждённая версия остаётся доступной.

В независимом варианте с разделяемой памятью остановка и удаление ресурсов выполняются отдельными командами. В варианте с очередью сообщений сервер завершает обработку и удаляет очередь при штатной остановке; именованные семафоры удаляются командой `mq_cleanup`.

## Журнал

События и итоговая статистика сохраняются в `logs/`. Для независимой SHM-реализации используется общий журнал сеанса, доступ к которому синхронизируется семафором. В журнал попадают чтения, начало подготовки, завершение стадий, проверка, публикация и отмена версии.

## Тестирование

```sh
make test
```

Скрипт `tests/check.py` проверяет:

- оба варианта с родительским процессом;
- режимы `READ_OLD` и `WAIT_NEW`;
- базу из одного элемента;
- несколько читателей и писателей;
- большое число стадий и размер базы 100000;
- повторяемость генерации при фиксированном seed;
- применение нескольких параметров командной строки и отклонение некорректных числовых аргументов;
- корректное завершение по Ctrl+C;
- отмену незавершённой публикации;
- независимые процессы с разделяемой памятью;
- независимые процессы с очередями сообщений;
- очистку IPC-ресурсов.

Тестовые конфигурации находятся в `tests/data/`. Подробные результаты приведены в `report.md`.
