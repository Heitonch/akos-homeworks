# Индивидуальное задание №2
## по дисциплине «Архитектура компьютера и операционные системы»

### Вариант 4. Читатели и писатели: чтение подтверждённых данных

Выполнил: Церенов Максим Джангарович  
Группа: БПИ253

## 1. Условие задачи

Необходимо разработать многопоточную консольную программу на языке C, моделирующую работу читателей и писателей с базой данных. База состоит из отсортированного одномерного массива положительных целых чисел и номера подтверждённой версии.

Читатели берут случайную запись опубликованной версии и выводят индекс, значение и произведение значения на номер записи. Писатели готовят новую версию за несколько стадий, проверяют её и публикуют целиком. Во время подготовки читатель не должен видеть промежуточное состояние массива. Одновременно новую версию может готовить только один писатель.

Программа учитывает размер и начальное содержимое базы, число читателей и писателей, число операций на участника, диапазон новых значений, количество стадий, стратегию поведения читателей и задержки. Режим с неограниченным количеством операций завершается по прерыванию пользователя.

## 2. Общая структура программы

За основу взята последовательная версия из ИДЗ №1. Сохранены структуры данных, имена основных функций, логика изменения массива, способ ввода параметров и формат консольного вывода. Основные изменения внесены в управление действиями участников и синхронизацию.

Программа состоит из файлов:
- `main.c` — ввод и проверка параметров, создание начальной базы;
- `simulation.h` — структуры `Db`, `Reader`, `Writer`, `Config`;
- `simulation.c` — потоки читателей и писателей, подготовка и публикация версий, синхронизация;
- `Makefile` и `CMakeLists.txt` — сборка проекта с поддержкой `pthread`.

Каждый объект `Reader` и каждый объект `Writer` соответствует одному отдельному потоку, создаваемому через `pthread_create`. Основная функция ждёт их завершения через `pthread_join`. В отличие от ИДЗ №1 действия читателей и писателей теперь могут выполняться одновременно.

## 3. Работа читателей

Каждый поток читателя выполняет заданное количество операций. Для очередного чтения он получает доступ к опубликованной базе под мьютексом, сохраняет номер версии, случайный индекс и значение элемента, а затем отпускает мьютекс. Последующая задержка и вывод завершения выполняются уже для сохранённых данных.

Таким образом, даже если во время чтения писатель опубликует другую версию, начатая операция относится к прежней версии. Номер записи считается как индекс плюс один. Для случайных значений у каждого потока есть собственное состояние генератора.

Поддерживаются две стратегии:

READ_OLD — читатель может начать чтение предыдущей подтверждённой версии, пока писатель формирует новую.

WAIT_NEW — если писатель готовит новую версию, читатель ждёт на условной переменной `pthread_cond_wait`, пока публикация не завершится. После сигнала читатель повторно проверяет состояние базы.

## 4. Работа писателей

Каждый писатель получает право на подготовку через семафор, значение которого равно единице. Пока один писатель его удерживает, другие писатели не начинают работу.

Писатель выделяет отдельный рабочий массив `buf` и копирует в него текущую подтверждённую базу. Далее массив обрабатывается по стадиям: на каждой стадии часть элементов заменяется случайными числами из указанного диапазона. В это время предыдущая подтверждённая версия остаётся доступной для чтения в режиме READ_OLD.

После всех стадий писатель сортирует рабочий массив функцией `qsort` и проверяет положительность значений и порядок элементов. При успешной проверке он захватывает мьютекс базы, копирует подготовленные значения в опубликованный массив и обновляет номер версии. Это одна критическая секция, поэтому читатель не может наблюдать частичную публикацию.

По окончании публикации флаг подготовки сбрасывается, ожидающие читатели уведомляются через `pthread_cond_broadcast`, а писатель освобождает семафор.

## 5. Синхронизация потоков

Используются следующие средства:

- `pthread_mutex_t mu` — защищает массив базы, номер версии и признак подготовки новой версии;
- `sem_t` через `sem_open` — разрешает подготовку только одному писателю одновременно;
- `pthread_cond_t changed` — позволяет читателям в режиме WAIT_NEW ждать завершения подготовки;
- отдельный мьютекс для консольного вывода — не даёт разным потокам перемешивать строки одного сообщения.

Семафор создаётся как именованный и сразу удаляется из пространства имён через `sem_unlink`; до завершения программы открытый дескриптор остаётся действительным. Такой способ используется для совместимости с Linux и macOS.

## 6. Проверка инвариантов

1. Не более одного писателя подготавливает новую версию. Это обеспечивается семафором со значением один.
2. Читатель не получает промежуточных данных. Писатель изменяет отдельный буфер, а чтение опубликованной базы выполняется под мьютексом.
3. Опубликованный массив отсортирован. Новая версия сортируется и проверяется до публикации.
4. Публикация неделима. Копирование массива и увеличение номера версии выполняются под общим мьютексом.
5. Начатое чтение относится к одной версии. Индекс, значение и номер версии сохраняются в начале операции до освобождения мьютекса.

## 7. Пользовательский интерфейс

Программа запускается в терминале и последовательно просит ввести размер и начальный массив, количество читателей и писателей, число операций каждого участника, границы новых значений, число стадий подготовки, стратегию и задержки.

Для вводимых чисел проверяются допустимые границы. Начальный массив должен состоять из положительных чисел в неубывающем порядке.

Во время выполнения выводятся начало подготовки версии, стадии работы писателя, чтение подтверждённых данных, ожидание читателя, проверка и подтверждение версии, публикация и итоговая статистика. Данные разных потоков могут появляться в разном порядке, потому что порядок выполнения зависит от планировщика ОС.

## 8. Сборка и запуск

Программа написана на C11 с использованием `libc`, системных функций POSIX и библиотеки `pthread`.

Сборка через Makefile: `make`.

Запуск: `./idz2`.

Для проверки готовых наборов данных: `./idz2 < data/old.txt`, `./idz2 < data/wait.txt`, `./idz2 < data/multi.txt`.

Для проверки проекта: `python3 tests/check.py` после сборки.

Проект можно также открыть в CLion и собрать с использованием `CMakeLists.txt`.

## 9. Завершение программы

При положительном числе операций каждый читатель завершает заданное число чтений, а каждый писатель — заданное число публикаций. Основной поток ожидает завершения всех запущенных потоков через `pthread_join`. После этого выводится итоговая статистика и освобождаются ресурсы.

Если число операций равно нулю, программа работает до `Ctrl+C`. Обработчик `SIGINT` сообщает основному потоку о прерывании. Новые операции не начинаются, ожидающие читатели разблокируются. Уже начатая подготовка версии завершается публикацией, а начатое чтение заканчивается со своей сохранённой версией. Затем потоки объединяются, семафор и остальные ресурсы освобождаются.

## 10. Результаты тестирования

Проверены следующие наборы параметров:

**Тест 1 — READ_OLD.** Начальная база [2 5 8 12 19], 2 читателя, 1 писатель, по 2 операции на участника, диапазон 1–20, 3 стадии. Результат: 4 чтения, 2 публикации, итоговая версия 3. Читатели могли работать со старой версией во время подготовки новой.

**Тест 2 — WAIT_NEW.** Та же база, 3 читателя, 2 писателя, по 4 операции на участника, 3 стадии. Результат: 12 чтений, 8 публикаций, итоговая версия 9. Пока версия готовилась, читатели выводили сообщения об ожидании и продолжали работу после публикации.

**Тест 3 — несколько писателей.** Та же база, 3 читателя, 4 писателя, по 3 операции на участника, 4 стадии. Результат: 9 чтений, 12 публикаций, итоговая версия 13. Подготовки разных писателей не пересекались.

**Тест 4 — минимальный размер базы.** Массив из одного элемента со значением 2147483647, 1 читатель и 1 писатель, по 3 операции на участника. Результат: 3 чтения, 3 публикации, итоговая версия 4, массив остался отсортированным и положительным.

**Тест 5 — завершение по сигналу.** Запущен неограниченный режим, затем отправлен `SIGINT`. Программа вывела `Stopped by user`, закончила уже начатую публикацию и завершилась без зависания.

Запуски показали соответствие итогового количества операций входным параметрам. При повторных запусках итоговые массивы оставались отсортированными и состояли из положительных чисел.
