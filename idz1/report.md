### Вариант 4. Читатели и писатели: чтение подтверждённых данных

## 1. Условие задания

Нужно разработать последовательную программу на языке C, которая моделирует работу читателей и писателей с базой данных.

База данных — это отсортированный одномерный массив положительных целых чисел. У базы есть номер текущей подтверждённой версии.

В модели есть два типа участников:
- читатели;
- писатели.

Читатель выбирает случайную запись из подтверждённой версии базы и выводит индекс, значение, номер записи и произведение значения на номер записи.

Писатель формирует новую версию базы в несколько стадий. Пока версия не подготовлена полностью, читатели не должны видеть промежуточные данные. После завершения подготовки новая версия проверяется и публикуется как подтверждённая.

## 2. Что делает программа

После запуска программа запрашивает у пользователя:
- размер базы;
- начальные значения массива;
- количество читателей;
- количество писателей;
- количество операций каждого участника;
- минимальное и максимальное новое значение;
- число стадий подготовки новой версии;
- стратегию работы читателей;
- задержки чтения, подготовки и подтверждения.

Начальная версия базы имеет номер 1.

## 3. Логика работы программы

Программа является последовательной. В каждый момент времени выполняется действие только одного участника.

Читатели и писатели представлены как отдельные объекты модели, а основной цикл программы выбирает, чьё действие выполнить следующим.

### Работа читателя

Читатель выбирает случайный индекс из текущей подтверждённой версии базы.

После этого программа выводит:
- номер версии;
- индекс;
- значение;
- номер записи;
- произведение значения на номер записи.

Например, если выбран индекс 3 и значение 12, то номер записи равен 4, а результат равен 48.

### Работа писателя

Писатель создаёт рабочую копию текущей базы. Эта копия недоступна читателям.

Подготовка новой версии разбивается на несколько стадий. На каждой стадии часть элементов рабочей копии заменяется случайными значениями из заданного диапазона.

После завершения всех стадий массив сортируется и проверяется. Проверяется, что все элементы положительные и массив отсортирован.

Если проверка успешна, версия подтверждается и публикуется. После этого номер версии увеличивается на 1.

## 4. Используемые структуры

В программе используются структуры Db, Reader, Writer и Config.

Db хранит размер массива, данные и номер подтверждённой версии.

Reader хранит номер читателя, количество оставшихся операций и количество выполненных чтений.

Writer хранит номер писателя, количество оставшихся операций, признак активной подготовки, номер текущей стадии, рабочий массив и количество выполненных публикаций.

Config хранит параметры моделирования.

## 5. Как выполняются условия задачи

1. Одновременно новую версию подготавливает только один писатель. В программе в каждый момент может быть только один активный писатель.

2. Читатель получает только подтверждённую версию. Писатель изменяет отдельный рабочий массив, а не основную базу.

3. Опубликованный массив всегда отсортирован. Перед публикацией массив сортируется и проверяется.

4. Публикация новой версии выполняется только после полной подготовки. Сначала завершаются все стадии, затем выполняется проверка и только после этого публикация.

5. Начатое чтение относится к одной версии. Операция чтения полностью выполняется за один шаг модели.

## 6. Стратегии читателей

В программе реализованы два режима.

READ_OLD — если новая версия готовится, читатель продолжает читать предыдущую подтверждённую версию.

WAIT_NEW — если новая версия готовится, читатель ждёт, пока она будет опубликована.

Хотя программа последовательная, оба режима реализованы для моделирования поведения системы.

## 7. Пользовательский интерфейс

Программа работает в консоли.

Пользователь по очереди вводит все параметры. Для числовых значений выполняется проверка корректности. Начальный массив вводится в неубывающем порядке и должен содержать только положительные числа.

Во время работы программа выводит основные события:
- начало моделирования;
- чтение читателем;
- начало подготовки новой версии;
- завершение каждой стадии;
- ожидание читателей;
- проверку новой версии;
- подтверждение и публикацию;
- итоговую статистику.

Для наглядности можно задать задержки в миллисекундах для чтения, подготовки и подтверждения.

## 8. Сборка и запуск

В проекте используются файлы:
- CMakeLists.txt
- Makefile
- main.c
- simulation.c
- simulation.h

Программа написана на C11.

Сборка через Makefile:

Запуск:

./idz1

Очистка:

make clean

Также программу можно собрать через CMake или из CLion.

## 9. Завершение программы

Если задано положительное число операций, каждый читатель выполняет указанное количество чтений, а каждый писатель — указанное количество публикаций. После этого программа завершается автоматически.

Если количество операций равно 0, программа работает без ограничения по числу шагов. В этом случае завершение выполняется с помощью Ctrl+C. Для этого используется обработка сигнала SIGINT.

Если в момент остановки писатель уже начал подготовку версии, программа сначала корректно завершает текущую публикацию, а затем заканчивает работу.

## 10. Результаты работы программы

### Тест 1

Параметры:

Размер базы — 5  
Начальная база — [2 5 8 12 19]  
Читатели — 2  
Писатели — 1  
Операций каждого участника — 2  
Диапазон новых значений — от 1 до 20  
Стадий подготовки — 3  
Стратегия — READ_OLD

Во время подготовки версии 2 читатели продолжали работать с подтверждённой версией 1.

После завершения трёх стадий версия 2 была проверена и опубликована.

Итоговая статистика:

Reads: 4  
Publications: 2

Результат соответствует параметрам: два читателя выполнили по две операции, один писатель выполнил две публикации.

В результате была разработана последовательная программа на языке C, моделирующая работу читателей и писателей с подтверждёнными версиями базы данных.

Программа поддерживает несколько читателей и писателей, моделирует подготовку новой версии в несколько стадий, не позволяет читателям видеть промежуточные данные, публикует только проверенные и отсортированные версии, поддерживает два режима поведения читателей и корректно завершается.

Основные требования задания выполнены.
