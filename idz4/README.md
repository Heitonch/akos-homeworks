# ИДЗ №4 — TCP-клиент-серверная модель

**Вариант 4. Читатели и писатели: чтение подтверждённых данных.**

Сохраняется предметная модель предыдущих ИДЗ: база — отсортированный массив положительных целых чисел с номером подтверждённой версии. Писатель готовит новую версию по стадиям, сервер проверяет и публикует её переключением буфера. Читатели получают только подтверждённые данные.

## Сборка

```sh
make
```

## Запуск

Сервер (на всех сетевых интерфейсах):

```sh
./bin/idz4 server --bind 0.0.0.0 --port 5050 --strategy READ_OLD
```

В отдельных терминалах:

```sh
./bin/idz4 reader --host 127.0.0.1 --port 5050 --id 1 --ops 5
./bin/idz4 writer --host 127.0.0.1 --port 5050 --id 2 --ops 2 --seed 42
./bin/idz4 observer --host 127.0.0.1 --port 5050 --id 90 --ops 0
```

Для запуска на разных компьютерах в параметре `--host` указывается адрес машины с сервером. Порт должен быть открыт в сетевом экране. Несколько читателей и писателей запускаются отдельными экземплярами с разными `--id`.

Параметры сервера: `--bind`, `--port`, `--strategy READ_OLD|WAIT_NEW`, `--ops`, `--stages`, `--size`, `--seed`. Параметры клиента: `--host`, `--port`, `--id`, `--ops`, `--seed`. Значение `--ops 0` означает непрерывную работу.

## Роли

- Сервер хранит подтверждённую базу, координирует единственного активного писателя и обслуживает TCP-соединения через `poll()`.
- Читатель запрашивает случайную запись и получает версию, индекс, значение, номер записи и произведение.
- Писатель отправляет команды начала, стадий, публикации или отмены.
- Наблюдатель периодически запрашивает агрегированное состояние сервера командой `STATUS`.

## Протокол

Построчные TCP-сообщения: `HELLO id`, `READ index`, `BEGIN seed`, `STAGE number`, `PUBLISH`, `ABORT`, `STATUS`, `QUIT`. Ответы также завершаются переводом строки.

`READ_OLD` позволяет читать предыдущую подтверждённую версию во время подготовки. При `WAIT_NEW` запросы читателей ожидают публикации или отмены. Публикация выполняется только после всех стадий и проверки массива. При потере соединения писателя незавершённая подготовка отменяется.

## Завершение и журнал

Клиенты завершаются после заданного числа операций или по Ctrl+C. Сервер завершается по Ctrl+C/SIGTERM, отменяет незавершённую публикацию, обслуживает ожидающих читателей последней подтверждённой версией и закрывает соединения. События и статистика записываются в `logs/idz4_server.log`.

## Тесты

```sh
make test
```

Проверяются чтение и публикация при `READ_OLD`, сводка наблюдателя и ожидание публикации при `WAIT_NEW`.
