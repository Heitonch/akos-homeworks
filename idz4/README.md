# ИДЗ №4 — TCP-клиент-серверная модель

**Вариант 4. Читатели и писатели: чтение подтверждённых данных.**

В ИДЗ 4 сохранена предметная модель предыдущих работ: база представляет собой массив положительных целых чисел с номером подтверждённой версии. Писатель готовит следующую версию по стадиям, сервер проверяет её и публикует переключением активного буфера. Читатели получают только подтверждённые данные.

## Состав проекта

| Файл | Назначение |
|---|---|
| `main.c` | разбор роли и аргументов командной строки |
| `server.c` | TCP-сервер, состояние базы, публикация версий и обработка клиентов |
| `client.c` | общая логика подключения, сигналов и задержек |
| `protocol.c` | отправка и приём построчных TCP-сообщений, проверка числовых параметров |
| `reader.c` | клиент-читатель |
| `writer.c` | клиент-писатель |
| `observer.c` | клиент-наблюдатель |
| `tests.sh`, `tests_protocol.py` | интеграционные проверки и проверки протокола |

## Сборка и тестирование

Нужна Linux-система и компилятор C с поддержкой C11.

```sh
make
make test
```

Сборка выполняется с предупреждениями `-Wall -Wextra -Wpedantic -Werror`. Исполняемый файл создаётся в `bin/idz4`.

## Запуск

Сервер на всех IPv4-интерфейсах:

```sh
./bin/idz4 server --bind 0.0.0.0 --port 5050 --strategy READ_OLD
```

В отдельных терминалах:

```sh
./bin/idz4 reader --host 127.0.0.1 --port 5050 --id 1 --ops 5
./bin/idz4 writer --host 127.0.0.1 --port 5050 --id 2 --ops 2 --seed 42
./bin/idz4 observer --host 127.0.0.1 --port 5050 --id 90 --ops 0
```

Для распределённого запуска клиентам передаётся IPv4-адрес компьютера, на котором работает сервер. TCP-порт сервера должен быть доступен по сети. Каждый клиент запускается отдельным процессом; для нескольких экземпляров одной роли используются разные `--id`.

### Параметры сервера

- `--bind IPv4` — адрес интерфейса для прослушивания, по умолчанию `0.0.0.0`.
- `--port PORT` — TCP-порт, по умолчанию `5050`.
- `--strategy READ_OLD|WAIT_NEW` — стратегия чтения.
- `--ops N` — количество операций клиента по умолчанию; `0` означает работу до остановки.
- `--size N` — размер массива, от 1 до 100000.
- `--stages N` — число стадий подготовки, не больше размера массива.
- `--min N`, `--max N` — диапазон значений новой версии.
- `--seed N` — начальное значение генератора.
- `--read-ms N` — задержка читателя перед отправкой запроса чтения (не блокирует сервер).
- `--prep-ms N` — задержка писателя между стадиями.
- `--confirm-ms N` — задержка писателя перед публикацией.

### Параметры клиента

- `--host IPv4` — адрес сервера, по умолчанию `127.0.0.1`.
- `--port PORT` — порт сервера, по умолчанию `5050`.
- `--id N` — идентификатор клиента.
- `--ops N` — число операций; `0` означает работу до сигнала остановки. Если параметр не задан, используется значение `--ops` сервера.
- `--seed N` — начальное значение для воспроизводимого псевдослучайного выбора записей читателем или подготовки версии писателем.

## Поведение

Сервер — единственный владелец базы и состояния публикации. Несколько TCP-клиентов обслуживаются через `poll()` в одном цикле событий.

- Читатель отправляет `READ index`. В ответ получает номер версии, индекс, значение, порядковый номер записи и произведение значения на номер записи.
- Писатель отправляет `BEGIN seed`, последовательно `STAGE number`, затем `PUBLISH`. При необходимости он может отправить `ABORT`.
- Наблюдатель отправляет `STATUS` и получает номер версии, размер базы, состояние подготовки и счётчики операций.

Читатель выбирает индекс записи псевдослучайно; сочетание `--seed` и `--id` задаёт воспроизводимую последовательность. При `READ_OLD` чтение во время подготовки выполняется из предыдущей подтверждённой версии. При `WAIT_NEW` запросы чтения помещаются в очередь и обслуживаются после публикации или отмены подготовки. Одновременно готовить новую версию может только один писатель. Наблюдателей и читателей может быть несколько.

Новая версия создаётся в неактивном буфере. Перед публикацией сервер сортирует массив и проверяет диапазон значений и порядок элементов. Номер версии меняется только после успешной проверки. При отмене подготовки или потере соединения писателя активный буфер остаётся неизменным.

## Завершение и журнал

Клиенты завершаются после заданного числа операций или по `Ctrl+C`/`SIGTERM`; ожидание ответа сервера прерывается сигналом остановки. При `QUIT` сервер отправляет `BYE` и закрывает соединение. Сервер завершает работу по `Ctrl+C`/`SIGTERM`: незавершённая подготовка отменяется, ожидающие читатели получают последнюю подтверждённую версию, соединения закрываются.

События и итоговые счётчики записываются в `logs/idz4_server.log`. Каталог создаётся при запуске сервера.
